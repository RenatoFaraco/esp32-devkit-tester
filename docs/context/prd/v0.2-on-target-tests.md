# PRD — esp32-devkit-tester v0.2 · Testes na placa

> Status: **rascunho** · Marco: M2 · só vale como critério quando a versão começar

## Objetivo
Gravar um firmware de teste (C/ESP-IDF, um binário por chip) e rodar testes que só a própria
placa consegue fazer, com os resultados mostrados pelo host no mesmo relatório estilo Jest.

## Já decidido
- Firmware em C com ESP-IDF puro, um build por alvo (ADR-001); testes escritos com Unity.
- Gravação só com confirmação na TUI (ADR-003); o host escolhe o binário pelo chip detectado.
- Protocolo de resultados próprio, em linhas ASCII versionadas, separável do log do IDF
  (ADR-005, proposta) → spec em `docs/context/spec/result-protocol.md`.

## Escopo previsto
| ID | Requisito |
|----|-----------|
| F1 | SRAM interna: March C- nas regiões livres do heap, por capacidade (`MALLOC_CAP_INTERNAL`) |
| F2 | PSRAM (quando o eFuse/sdkconfig indicar): tamanho real detectado vs declarado + March C- |
| F3 | Flash: JEDEC/tamanho pelo próprio chip, apagar/escrever/ler na partição `scratch` |
| F4 | CPU: núcleos ativos, frequência configurada vs medida, tarefa em cada núcleo (dual-core) |
| F5 | Relógios/temporizadores: `esp_timer` vs RTC, sensor de temperatura interno (se houver) |
| F6 | Emissor de resultados: início/fim de suíte, teste com status, duração e mensagem |
| H1 | Gravar o binário do chip, abrir o console, separar linhas do protocolo do resto |
| H2 | Integrar as suítes da placa no mesmo relatório da v0.1; timeout por teste |

## Em aberto
Gravar na flash ou carregar na RAM (como o stub do esptool)? Afeta o "não destrutivo".
